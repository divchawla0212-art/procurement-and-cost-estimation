Procurement Comparison Portal · Pipeline reference

How a vendor ZIP becomes a defensible bid comparison

Nineteen steps from upload to exported comparison. Exactly one of them asks a language model to make a judgement — the other eighteen are deterministic Python you can unit-test, re-run, and defend when an award gets challenged. This page walks each step and what it buys you.

A · Set up the tender

portal/app.py · procurement/project.py

Everything the run needs is captured on disk before a single document is read. Nothing lives in session memory, so a browser refresh or a portal restart costs you nothing.

  1. 01

    create_project() project.py

    Slugifies the tender name, creates requirements/ and vendors/, and writes project.json holding the target currency, FX table, vendor list and status.

    Why it helps Each tender gets an isolated, inspectable folder. You can zip a project and hand the whole evidence trail to an auditor, or re-open it six months later during a challenge.

  2. 02

    requirements upload app.py

    Stores the MR / RFQ under requirements/ and records the filename on the project. It is filed and never opened — no step downstream reads it.

    Why it helps The spec travels with the evidence pack today. It is also the hook the compliance baseline will plug into — parse this once and every bid can be scored against it.

  3. 03

    unpack_vendor_zip() project.py

    Treats each top-level folder in the archive as one vendor. Resolves every destination with realpath and refuses anything landing outside vendors/; skips __MACOSX, dotfiles and ~$ Office lock files. Writes the roster back to the project.

    Why it helps One drag-and-drop replaces manual vendor entry, and the folder names become the identities used to join every later table. The containment check means a malicious or malformed archive cannot write into your filesystem.

  4. 04

    FX rates app.py

    Parses EUR=1.08, AED=0.27 style pairs into project.fx_rates, silently dropping malformed entries.

    Why it helps The exchange rate is the single most contestable assumption in a multi-currency comparison. Keeping it as editable project data — not a constant in code — means you can restate the whole comparison at a different rate in seconds.

B · Run ingestion

procurement/pipeline.py · shared/llm/factory.py

One button in the portal calls run_ingestion(), which loads validated project state, builds an LLM client, then walks the vendors one at a time.

  1. 05

    load_project() pipeline.py

    Re-reads project.json through Pydantic rather than trusting whatever the UI was holding.

    Why it helps The run is driven by what is actually on disk, so a run is reproducible from the folder alone — no hidden UI state can change the result.

  2. 06

    get_client() factory.py

    Reads LLM_PROVIDER / LLM_MODEL and returns an Anthropic, OpenAI, Gemini, Bedrock or mock client behind one narrow classify_structure() interface.

    Why it helps Switching provider is one environment variable, not a refactor. The mock client is what lets the whole pipeline be tested in CI without an API key or a cent of spend.

for each vendor in project.vendors

  1. 07

    vendor_files() project.py

    Walks the vendor folder recursively, drops hidden and lock files, returns the list sorted.

    Why it helps Sorting makes file order deterministic, so two runs over the same folder resolve the same quote document — a prerequisite for reproducible results.

  2. 08

    pick_quote() quote_select.py

    Scores filenames: +100 for quotation / quote / offer / proposal / techno / commercial, −50 for bom / datasheet / deviation / mom / spec / layout / p&id / spares / drawing, +5 for .pdf or .xlsx, shortest filename wins ties.

    Why it helps KERUI ships 21 documents and only one carries the price. This finds it with zero model calls and zero operator effort — and because the portal prints the chosen filename next to each vendor, a wrong pick is visible before you trust the number.

  3. 09

    read_text() loaders.py

    Dispatches on extension. .xlsx goes through openpyxl in read-only, data_only mode and is flattened to Sheet | A1=val | B1=val lines.

    Why it helps Emitting the cell address alongside every value keeps the spreadsheet's coordinates intact in the text the model sees — which is what makes cell-level provenance possible rather than a vague "it was somewhere in the workbook".

  4. 10

    read_pdf_text() — tier 1 & 2 loaders.py

    Tries the pdftotext -layout CLI first, then falls back to pypdf, keeping whichever returns more text. Each tier only fires if the previous produced under 200 characters.

    Why it helps -layout preserves column alignment, so a price table survives as a readable table instead of collapsing into scrambled tokens. Two cheap local extractors handle the overwhelming majority of vendor PDFs at no API cost.

  5. 11

    transcribe_pdf() pdf_llm.py fallback

    If the text layer is still thin, the raw PDF is sent to a vision-capable model as a native document block and transcribed verbatim. The portal only wires this tier in when ANTHROPIC_API_KEY is set — it uses Anthropic's own PDF document input, so it stays available even when extraction itself is running on OpenAI or Gemini. Without that key pdf_fallback is None and the tier is skipped.

    Why it helps Six of KERUI's files are image-only scans — layouts, single-line diagrams, nameplate drawings. Without this tier they would silently yield empty text and the vendor would look like it quoted nothing. It costs nothing when the text layer is healthy — but it degrades quietly: with no Anthropic key set, a scanned quote extracts as empty rather than raising.

  6. 12

    classify_structure() extract.py the only inference step

    Sends bid_extract_v1 plus the document text and gets back a BidExtraction: currency, base price, VAT flag and rate, freight amount and basis, discount, optional line items, delivery time, Incoterms, payment terms, engine make. The prompt explicitly forbids converting currencies, computing totals, or inventing values.

    Why it helps The model does the one thing it is genuinely better at than code — reading unstructured commercial prose — and is barred from arithmetic. Every number it returns should be findable verbatim in the source document, which makes verification a text search rather than a re-derivation.

  7. 13

    VendorBid + ProvenanceRef extract.py

    Pydantic validates the model's output against the schema, then wraps it with the source document path and the extractor stamp anthropic:bid_extract_v1.

    Why it helps Malformed output is rejected at the boundary instead of poisoning the comparison. And every figure carries which document and which prompt version produced it — so when a losing bidder challenges the evaluation, you can name the page.

  8. 14

    except → extraction_status="failed" extract.py per-vendor

    Any failure — unreadable file, no quote document, invalid model output — is caught per vendor and recorded as a failed bid with the error text in notes.

    Why it helps One bad vendor folder cannot abort the tender. You get a table with three usable rows and one clearly flagged row, plus the reason, instead of a stack trace and nothing.

  9. 15

    normalize_bid() normalize.py

    Walks the as-quoted price through four ordered adjustments, each recording a NormalizationAdjustment with its kind, description, from-value, to-value and delta.

    StepRuleWhat it removes from the comparison
    currency × fx_rate Different quoting currencies. A missing rate is logged as an explicit "assumed 1.0" adjustment rather than applied silently.
    vat ÷ (1 + rate) One vendor quoting tax-inclusive against another quoting ex-tax.
    freight + amount × fx EXW vs CIF. Puts everyone on a freight-included basis.
    discount − total × pct Headline price vs the price actually payable.

    Why it helps This is the step that makes the numbers comparable at all — and because each adjustment is itemised rather than folded into one figure, the path from quoted price to comparable total is fully auditable and reversible. The portal renders these as a per-vendor table.

↻ repeat for the next vendor

C · Converge, persist, export

procurement/compare.py · export.py

The per-vendor results join back into one table, get written to disk, and leave the system in the formats procurement actually circulates.

  1. 16

    build_comparison() compare.py

    Joins raw bids to normalized bids on vendor name and emits one ComparisonRow per vendor carrying both the as-quoted price and the normalized total, alongside delivery terms, lead time, payment terms and engine make.

    Why it helps Keeping the raw and normalized figures side by side means a reviewer can see what a vendor actually wrote and what you compared — the adjustment is visible, not hidden.

  2. 17

    sort by (is_none, total) compare.py

    Orders by normalized total ascending, with the null-total key sorting failed extractions to the bottom.

    Why it helps Cheapest first, and failed rows sink instead of sorting as zero and falsely topping the table — a small detail that prevents a very expensive misread.

  3. 18

    dataset.json + status="done" pipeline.py

    Writes bids, normalized bids and the comparison table into the project folder and marks the project complete.

    Why it helps Results outlive the process. Re-opening the project renders instantly from disk with no re-extraction, so reviewing a tender is free after the first run.

  4. 19

    export — xlsx · csv · raw JSON export.py · app.py

    Renders the sortable table, offers Excel and CSV downloads on a fixed nine-column header, and exposes every vendor's raw extracted bid plus its adjustment ledger in expanders.

    Why it helps The comparison lands in the format that gets circulated and marked up. The raw JSON alongside it means anyone who doubts a cell can trace it back to the extraction without asking you.

What the shape buys you

  • One inference call per vendor. Steps 01–11 and 13–19 are deterministic; only step 12 (and step 11 on scanned files) involves a model. The blast radius of a model error is one well-defined schema, not the whole result.
  • Arithmetic never leaves Python. The prompt forbids the model from converting or totalling. Every number in the final table was either copied verbatim from a document or computed by code with unit tests behind it.
  • Failure is per-vendor, never global. Bad archives, missing quotes, unreadable PDFs and invalid model output all degrade to a flagged row.
  • Every derived figure is traceable. Provenance on the extraction, an itemised ledger on the normalization, raw JSON in the UI.
  • Reproducible from the folder alone. Sorted file walks, on-disk project state, and a versioned prompt string mean a re-run months later produces a comparable result.

Not in the pipeline yet

  • The requirements document is stored but never parsed. Nothing checks a bid against the MR, so there is no technical compliance flag and no should-cost anchor.
  • Only one document per vendor is read. pick_quote() returns a single file, so deviation forms, spares lists and datasheets never reach extraction — which is exactly the material a compliance check would need.
  • Ranking is price-only. Delivery time and payment terms are carried into the table but not scored, so there is no weighted recommendation.
  • Extraction blocks the request. A run holds the Streamlit thread with no progress, retry or cancel.
